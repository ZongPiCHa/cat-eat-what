# 06 · 上架与合规手册

> 目标：公开上架微信小游戏。  
> 重要：本文是项目规划清单，不构成法律意见。微信平台和国家新闻出版署的政策会调整，正式申报前必须以官方最新要求、出版单位和专业顾问的意见为准。

---

## 1. 先看结论

公开上架微信小游戏，最长的一条线不是写代码，而是**资质**：

```
企业主体
  → 微信认证
  → 小游戏账号 + 游戏类目
  → 小程序/小游戏备案
  → 软件著作权
  → 游戏版号（通过出版单位）
  → 实名认证 + 防沉迷
  → 隐私政策 + 内容合规
  → 提交审核 → 发布
```

**建议：开发和资质并行。**  
代码 2-3 个月能做完，版号可能 6-12 个月，不要等代码写完才开始。

没有版号时，可以先发「体验版」给 2-4 个朋友测试，但不能公开推广、开广告或内购。

---

## 2. 小游戏 vs 小程序

| 项目 | 微信小游戏 | 微信小程序 |
|---|---|---|
| 入口 | `game.js`，游戏运行时 | WXML/JS，页面框架 |
| 适合 | 游戏产品 | 工具、服务、内容 |
| 公开上架游戏 | 正确类目 | 游戏内容可能被要求改类目/驳回 |
| 游戏资质 | 需要游戏类目、版号等 | 同样受游戏内容监管 |
| 本项目 | **采用** | 不采用 |

**不要把游戏包装成「工具」去规避游戏资质。** 审核可能驳回，后续也可能被下架，影响账号信用。

## 3. 主体与账号

### 3.1 主体选择

公开运营游戏，建议按**企业主体**规划：

- 营业执照。
- 对公账户（部分认证/结算需要）。
- 法人/负责人信息。
- 企业微信认证（约 300 元/年）。

个人主体：

- 可以注册部分小程序能力。
- 游戏类目/公开运营通常受限。
- 是否能发布小游戏，以微信公众平台当前规则为准，不建议把公开上架押在个人主体上。

### 3.2 注册流程

1. 打开微信公众平台 `mp.weixin.qq.com`。
2. 注册「小游戏」账号（或小程序账号后选择游戏类目，按平台引导）。
3. 填写邮箱、主体信息、管理员信息。
4. 完成主体验证（对公打款/法人验证）。
5. 完成微信认证。
6. 设置名称、图标、简介、类目。
7. 绑定开发者/体验成员。

### 3.3 名称与图标

- 名称需唯一，不与现有小游戏/商标冲突。
- 上线前做商标检索（中国商标网）。
- 图标原创，不使用未授权 IP、明星、品牌包装。
- 简介不夸大、不诱导、不含敏感词。

## 4. 备案

### 4.1 小程序/小游戏备案

- 微信公众平台 → 设置 → 基本设置 → 小程序备案。
- 提交主体信息、负责人信息、服务内容、域名等。
- 备案通过后才能正式发布。
- 周期通常 1-4 周，视属地管局。
- 备案信息变更需更新。

### 4.2 域名 ICP 备案

如果自建服务器：

- 域名必须完成 ICP 备案。
- 备案主体与小程序主体尽量一致。
- 网站名称/服务内容与实际一致。
- 备案通过后才能在微信后台配置合法域名。

### 4.3 公安备案

- 按属地要求，部分网站/服务需要公安联网备案。
- 以云厂商和属地公安指引为准。

### 4.4 游戏备案/版号

- 游戏版号与 ICP 备案是两件事。
- 版号由出版单位向国家新闻出版署申报。
- 具体材料、流程以出版单位指导为准。

## 5. 软件著作权（软著）

### 5.1 作用

- 游戏类目/版号申报常用材料。
- 证明代码/美术归属，防侵权纠纷。
- 部分渠道/合作需要。

### 5.2 材料

- 软件著作权登记申请表。
- 源代码前后各 30 页（共 60 页），不足 60 页全交。
- 软件说明书/操作手册。
- 主体证明文件。
- 委托书（如代办）。

### 5.3 周期与费用

- 自行申请：官方登记费已取消，周期约 1-3 个月（以版权中心为准）。
- 代办/加急：几百到几千元，周期可缩短。
- 建议在开发中期就申请，不要等上线。

### 5.4 名称

- 软著名称与游戏名称可不同，但建议关联。
- 版本号、开发完成日期如实填写。
- 代码中避免使用未授权第三方代码/素材。

## 6. 游戏版号

### 6.1 是什么

游戏版号（ISBN）是国内网络游戏公开运营的出版审批。没有版号，游戏类目通常无法正式上架、开广告或内购。

### 6.2 谁来申请

- 需要具备网络出版服务资质的出版单位申报。
- 研发方通常作为著作权人/运营方配合提供材料。
- 个人开发者一般需要通过出版单位/代理合作。

### 6.3 常见材料

- 游戏名称、类型、玩法说明。
- 软著证书。
- 完整游戏客户端/安装包/体验账号。
- 游戏截图、视频、脚本。
- 防沉迷/实名方案。
- 内容自查报告。
- 出版单位要求的其他材料。

### 6.4 周期与成本

- 周期通常 6-12 个月甚至更长，受政策、材料、排队影响。
- 成本为数万元级起，具体以出版单位/代理报价为准。
- 不保证一次通过；可能需要修改内容后重新申报。
- 版号有有效期/运营要求，按出版单位指导执行。

### 6.5 风险

- 名称、内容、玩法可能被要求修改。
- 涉及随机抽取/付费/未成年人保护的设计要特别谨慎。
- 政策变化可能影响审批节奏。
- 没有版号就公开推广属于高风险行为。

### 6.6 建议

1. **现在就联系出版单位/代理**，了解材料清单和报价。
2. 先做体验版内测，收集数据和口碑。
3. 版号材料中的游戏版本尽量与上线版本一致。
4. 保留所有素材/音乐/字体授权记录。
5. 不要在版号未定时投入大量买量/推广。

## 7. 实名认证与防沉迷

### 7.1 要求

公开运营的游戏需要：

- 用户实名认证。
- 未成年人防沉迷限制。
- 按国家新闻出版署现行规定执行游戏时长/时段限制。
- 不得向未成年人提供诱导性付费（首版无付费，但仍需合规）。

### 7.2 实现方式

- 接入微信平台提供的实名/防沉迷能力（以当前开放能力为准）。
- 或自建实名系统（成本高，需合规评估）。
- 游戏内展示防沉迷提示、家长监护说明。
- 记录必要的认证状态，不超额收集个人信息。

### 7.3 首版策略

- 不做内购、不做广告，降低未成年人付费风险。
- 仍要完成实名/防沉迷接入，不能因为免费就跳过。
- 单人练习/审核模式也要走同一套合规逻辑。

## 8. 隐私与数据合规

### 8.1 收集范围

| 数据 | 用途 | 是否必要 |
|---|---|---|
| openid | 登录、房间座位、重连 | 必要 |
| 设备基础信息 | 适配、排障 | 必要 |
| 游戏行为日志 | 平衡、排障、反作弊 | 必要 |
| 崩溃日志 | 稳定性 | 必要 |
| IP | 安全/限流 | 可选，尽量脱敏 |
| 头像/昵称 | 首版不收集 | 不需要 |
| 位置/通讯录/相册/麦克风 | 不收集 | 不需要 |

### 8.2 隐私政策

必须包含：

- 运营主体名称、联系方式。
- 收集哪些数据、为什么收集。
- 数据如何存储、保存多久、与谁共享。
- 用户如何查询/更正/删除数据。
- 未成年人保护条款。
- 第三方 SDK 清单（Cocos、微信、CDN、日志等）。
- 政策更新方式。

### 8.3 授权

- 首次启动展示隐私政策摘要。
- 使用微信隐私授权 API，未同意前不收集非必要信息。
- 不默认勾选、不强制授权非必要权限。
- 提供拒绝后的基础可用路径（如仅浏览）。

### 8.4 数据安全

- HTTPS/WSS 传输。
- 服务端最小权限。
- 日志脱敏。
- 定期清理无用数据。
- 数据删除请求有流程和响应时限。

### 8.5 第三方

- Cocos Creator：引擎运行时，确认其数据收集行为。
- 微信：登录、分享、支付（首版无支付）。
- CDN/日志/监控：列入第三方清单。
- 不使用来源不明的统计/广告 SDK。

## 9. 内容合规

### 9.1 本游戏的内容风险

| 内容 | 风险 | 处理 |
|---|---|---|
| 猫猫乱斗 | 暴力 | 卡通打闹、无血、无死亡、无武器伤害写实 |
| 食物武器 | 危险物品 | 都是餐具/食物，不出现刀剑枪 |
| 分数竞争 | 赌博联想 | 不涉及金钱/抽奖/押注 |
| 分享 | 诱导分享 | 不承诺奖励、不强制分享 |
| 聊天 | UGC | 首版不做自由聊天 |
| 昵称 | UGC | 系统生成，不接受输入 |
| 酒精/烟草 | 不良引导 | 食材不含酒/烟 |
| 食物浪费 | 价值观 | 结算强调「好好吃饭」，不鼓励浪费 |

### 9.2 文案红线

避免：

- 赌、押注、梭哈、赢钱。
- 杀死、血、爆头、尸体。
- 诱导分享、分享解锁、分享得奖励。
- 虚假宣传、绝对化用语。
- 未成年人不宜内容。

推荐：

- 打闹、敲一下、晕乎乎、猫猫全都要。
- 今晚吃 X、全票通过、双拼。
- 好好吃饭、别浪费。

### 9.3 视觉红线

- 无血、无伤口、无恐怖表情。
- 无赌博元素（筹码、老虎机、转盘抽奖）。
- 无现实品牌包装。
- 无未授权 IP。
- 无高频闪烁。

### 9.4 音乐/字体/素材

- 全部商用授权。
- 保留 license 文件。
- 不使用影视/游戏/动漫 BGM。
- 不使用未授权商业字体。
- 不用微信表情包做商业素材。

## 10. 审核准备

### 10.1 审核员怎么玩

多人游戏最大的审核风险是「审核员凑不齐人」。必须提供：

- **单人练习模式**：玩家 + 3 个 AI，完整两关 + 结算。
- 首页显眼入口，无需登录/房间。
- 完整规则说明和操作提示。
- 服务器稳定，审核期间可用。
- 如必须多人，提供房间号/测试账号/机器人补位。

### 10.2 审核材料

- 游戏名称、简介、玩法说明。
- 截图/录屏。
- 操作说明（跳/蹲、摇杆/攻击/闪避）。
- 单人练习入口说明。
- 隐私政策/用户协议链接。
- 防沉迷/实名说明。
- 测试房间号（如需要）。
- 版本号、更新说明。

### 10.3 审核常见驳回原因

- 类目/资质不符。
- 游戏内容与提交材料不一致。
- 无法体验核心玩法。
- 隐私政策缺失/与实际收集不符。
- 诱导分享。
- 内容低俗/暴力/赌博。
- 服务器不可用/频繁崩溃。
- 名称/图标侵权。

### 10.4 审核通过后

- 先小范围发布，观察崩溃/延迟/投诉。
- 保留回滚版本。
- 监控评价和反馈。
- 按需更新隐私政策/版本说明。

## 11. 体验版路径（开发期）

在版号/正式审核完成前，用体验版给朋友玩：

1. 微信开发者工具上传代码。
2. 微信公众平台 → 版本管理 → 设为体验版。
3. 生成体验版二维码。
4. 在成员管理中添加体验成员（人数上限以后台为准，4 个朋友足够）。
5. 分享体验版卡片/二维码。

体验版限制：

- 只对体验成员开放。
- 不能公开推广、开广告、内购。
- 通常不进入正式审核，也不需要版号。
- 仍要遵守内容/隐私规范。
- 服务器域名仍需配置（真机校验）。

**体验版是验证玩法的最佳方式，不是正式上架。**

## 12. 广告与内购（后续）

### 12.1 广告

- 需要开通流量主，通常有用户量/条件门槛。
- 广告内容需合规，不能诱导点击。
- 首版不做，避免影响体验和审核。
- 后续可考虑结算页激励视频（需评估政策）。

### 12.2 内购

- 虚拟支付涉及支付资质、iOS 限制、未成年人保护。
- 首版不做。
- 如后续做，需评估文网文、支付、发票、退款、客服等。
- 不要设计抽奖/开箱等高风险机制。

### 13.1 时间线（参考）

| 事项 | 周期 | 备注 |
|---|---|---|
| 企业主体/认证 | 1-2 周 | 提前准备执照/对公 |
| 小游戏账号/类目 | 1-2 周 | 与认证并行 |
| 小程序/小游戏备案 | 1-4 周 | 属地管局 |
| 软著 | 1-3 个月 | 可加急 |
| 版号 | 6-12+ 个月 | 最长路径 |
| 实名/防沉迷接入 | 1-2 周 | 开发量 |
| 隐私/内容整改 | 1-2 周 | |
| 审核 | 1-2 周 | 可能反复 |
| **开发** | **2-3 个月** | 与资质并行 |

### 13.2 预算（参考）

| 项目 | 费用 |
|---|---|
| 微信认证 | 约 300 元/年 |
| 域名 | 30-80 元/年 |

| 版号 | 数万元级起，以出版单位报价为准 |
