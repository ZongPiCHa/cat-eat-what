# 05 · 部署与运维手册

> 目标：让一个没有运维经验的人，也能按步骤把服务端和微信小游戏跑起来。  
> 推荐：腾讯云轻量服务器 2C4G + Docker + Caddy；单实例起步，后续水平扩展。

---

## 1. 环境划分

| 环境 | 用途 | 服务器 | 微信版本 |
|---|---|---|---|
| 本地 | 开发调试 | 本机 Node + 微信开发者工具 | 开发版 |
| 测试 | 团队内测 | 测试服（可与生产共用小配置） | 体验版 |
| 生产 | 公开运营 | 正式服务器 | 正式版 |

建议至少准备：

- 1 台测试/生产服务器（小团队可先用一台，正式上线前再拆）。
- 1 个域名（可复用二级域名）。
- 1 个微信小游戏账号。
- 1 个对象存储/CDN（放美术音频）。

---

## 2. 推荐部署拓扑

```
微信小游戏
   │ HTTPS / WSS
   ▼
Caddy（443，自动 HTTPS）
   │
   ├─ /api/*  → Node.js HTTP (3000)
   └─ /ws     → Node.js WebSocket
   │
   ▼
Node.js 20 + TypeScript
   │
   ├─ RoomManager（内存）
   └─ Redis（可选，多实例/会话/限流）
```

- Caddy 负责 TLS、反向代理、WebSocket 升级。
- Node 服务只监听本机/内网端口，不直接暴露公网。
- Redis 只在需要多实例或持久会话时启用。
- 首版不需要数据库；战绩落库可后加。

---

## 3. 服务器选型

### 3.1 推荐

| 项目 | 建议 |
|---|---|
| 云厂商 | 腾讯云（与微信生态近） |
| 产品 | 轻量应用服务器 |
| 配置 | 2 核 4G，系统盘 60GB+ |
| 地域 | 上海 / 广州（靠近用户） |
| 系统 | Ubuntu 22.04 LTS |
| 带宽 | 5-10Mbps 起步，按量/峰值 |
| 价格 | 约 100-200 元/月（以实际活动为准） |

### 3.2 为什么不是最低配

- Node + Redis + Caddy + 日志会占内存。
- 2G 能跑，但压测/构建/日志轮转容易吃紧。
- 4G 留出余量，避免半夜 OOM。

### 3.3 云托管备选

如果你不想管服务器，可以用微信云托管/腾讯云 CloudBase Run：

- 优点：免域名备案、自动扩缩容、与微信生态集成。
- 注意：WebSocket 长连接支持、超时、计费方式要以当前文档为准。
- 如果云托管对 WSS 支持不满足，仍建议用轻量服务器。

## 4. 域名、备案与 HTTPS

### 4.1 域名

- 购买一个域名，例如 `example.com`。
- 规划子域名：
  - `api.example.com`：HTTP API
  - `ws.example.com`：WebSocket（也可复用 api 域名）
  - `cdn.example.com`：静态资源
- 正式环境必须 HTTPS/WSS，不能使用 IP。

### 4.2 ICP 备案

- 大陆服务器必须完成 ICP 备案。
- 在云厂商备案系统提交：主体信息、网站信息、负责人核验。
- 周期通常 1-4 周，提前做。
- 备案通过后，域名才能解析到大陆服务器并提供 Web 服务。

### 4.3 SSL 证书

- 使用 Caddy 自动申请 Let's Encrypt 证书，自动续期。
- 或使用云厂商免费证书，手动配置 Nginx。
- 证书到期告警必须配置。

### 4.4 微信后台配置

微信小游戏后台 → 开发管理 → 开发设置 → 服务器域名：

| 类型 | 填写 |
|---|---|
| request 合法域名 | `https://api.example.com` |
| socket 合法域名 | `wss://ws.example.com` |
| downloadFile 合法域名 | `https://cdn.example.com` |
| uploadFile 合法域名 | 如无上传可不填 |

注意：

- 域名必须已备案、HTTPS 有效、不能带端口（默认 443）。
- 开发者工具「不校验合法域名」只用于本地；真机体验版/正式版会强制校验。
- 修改域名后需要重新编译/上传版本才能生效。

## 5. 服务器初始化

### 5.1 基础软件

- 更新系统。
- 安装 Docker、Docker Compose。
- 安装 Caddy（或用 Docker）。
- 配置时区 `Asia/Shanghai`。
- 创建非 root 部署用户。
- 配置 SSH 密钥登录，禁用密码登录。
- 防火墙只开放 22、80、443。

### 5.2 目录结构

```
/opt/cat-eat-what/
├─ docker-compose.yml
├─ Caddyfile
├─ .env
├─ data/
│  └─ redis/
└─ logs/
```

### 5.3 环境变量

`.env`（不要提交到 Git）：

```
NODE_ENV=production
PORT=3000
APP_ID=wx...
APP_SECRET=...
JWT_SECRET=...
REDIS_URL=redis://redis:6379
LOG_LEVEL=info
MAX_ROOMS=100
CLIENT_MIN_VERSION=1.0.0
```

- `APP_SECRET` 只放服务器。
- `JWT_SECRET` 使用随机长字符串。
- 定期轮换密钥，泄露时立即重置 AppSecret。

### 5.4 Docker Compose 服务

- `api`：Node 服务，暴露 3000（仅内网）。
- `redis`：可选，持久化 AOF。
- `caddy`：暴露 80/443，反向代理。
- 所有服务设置 `restart: unless-stopped`。
- 健康检查：`/healthz`。
- 日志驱动限制大小，避免磁盘打满。

### 5.5 Caddy 配置要点

- `api.example.com` 反向代理到 `api:3000`。
- `ws.example.com` 反向代理到 `api:3000`，支持 WebSocket Upgrade。
- 自动 HTTPS。
- 设置合理的超时：
  - WebSocket 读超时 > 心跳间隔。
  - 请求体大小限制。
- 开启访问日志（脱敏）。

## 6. 发布流程

### 6.1 服务端

1. 本地通过测试。
2. 构建 Docker 镜像。
3. 推送镜像到镜像仓库（腾讯云 TCR/Docker Hub 私有）。
4. 服务器拉取新镜像。
5. `docker compose up -d` 滚动重启。
6. 检查 `/healthz` 和日志。
7. 观察 10 分钟：错误率、在线人数、延迟。

### 6.2 客户端

1. Cocos Creator 构建微信小游戏。
2. 微信开发者工具打开构建目录。
3. 上传版本，填写版本号和备注。
4. 设为体验版，团队真机测试。
5. 测试通过后提交审核。
6. 审核通过后发布。

### 6.3 版本兼容

- 客户端启动检查 `minClientVersion`。
- 服务端至少兼容当前线上版本和上一个版本。
- 协议新增字段可向后兼容；删除/修改字段需升版本。
- 紧急回滚：
  - 服务端保留上一个镜像 tag。
  - 客户端使用微信后台的版本回退（如支持）或重新上传旧版本。

## 7. CI/CD

### 7.1 首版建议

- 服务端：GitHub Actions + Docker 构建 + SSH 部署。
- 客户端：本地/手动构建上传，先不自动化。
- 共享配置：CI 中运行类型检查和单元测试，防止两端不一致。

### 7.2 后续自动化

- Cocos CLI 构建。
- `miniprogram-ci` 上传（需确认小游戏支持情况）。
- 自动生成版本号、变更日志。
- 自动跑集成测试（多 WS 客户端）。

### 7.3 CI 检查项

- TypeScript 编译。
- ESLint/Prettier。
- 单元测试。
- 共享配置一致性校验。
- Docker 镜像构建。
- 安全扫描（依赖漏洞）。

## 8. 监控与日志

### 8.1 必看指标

| 指标 | 目标 | 告警 |
|---|---|---|
| 服务在线 | 100% | 不可用 > 1 分钟 |
| HTTP 5xx 率 | < 1% | > 5% |
| WS 异常断开率 | < 5% | > 10% |
| 房间创建成功率 | > 99% | < 95% |
| 在线人数 | 正常波动 | 异常掉零 |
| tick 延迟 P95 | < 20ms | > 100ms |
| 平均 RTT | < 100ms | > 250ms |
| 内存使用 | < 70% | > 85% |
| 磁盘使用 | < 70% | > 85% |

### 8.2 日志

- JSON 结构化日志。
- 字段：时间、级别、服务、房间号、playerId、事件、耗时、错误。
- 不记录 token、AppSecret、完整 openid。
- 日志轮转：按天/大小，保留 30 天。
- 关键事件：
  - 房间创建/销毁。
  - 玩家加入/离开/断线/重连。
  - 游戏开始/结束。
  - 异常输入/限流。
  - 服务启动/关闭。

### 8.3 告警渠道

- 企业微信机器人（推荐，免费）。
- 邮件。
- 短信（仅严重故障）。

### 8.4 客户端监控

- `wx.onError`、`wx.onUnhandledRejection`。
- 关键流程埋点。
- 崩溃率、加载失败率、断线率。
- 首版可用微信自带数据助手 + 自建 `/api/log`。

## 9. 数据与备份

### 9.1 首版

- 房间状态在内存，不落库。
- 战绩不持久化，重启丢失进行中对局。
- 日志保留 30 天。
- Redis 可选，开启 AOF。

### 9.2 后续

- PostgreSQL 存战绩、排行榜、审计。
- 每日自动备份，保留 7-30 天。
- 备份加密，异地存储。
- 定期演练恢复。

### 9.3 隐私

- 日志中的 openid 脱敏/哈希。
- 不记录聊天内容（首版无聊天）。
- 提供数据删除流程。
- 隐私政策与实际收集一致。

## 10. 扩展与容量

### 10.1 单实例

- 目标 50 活跃房间 / 200 CCU。
- 2C4G 足够。
- 先压测再上线。

### 10.2 多实例

当单实例不够：

1. Redis 保存房间注册表：`roomId → instanceId`。
2. 网关/负载均衡按 roomId 哈希转发。
3. 或使用一致性哈希。
4. 会话、限流、重连令牌放 Redis。
5. 服务端无状态化，房间状态可快照/恢复。

### 10.3 房间分片

- 按 roomId 前缀/哈希分配实例。
- 创建房间时选择负载最低的实例。
- 玩家加入时按 roomId 路由。
- 需要网关或服务发现；首版不做。

### 10.4 优雅关闭

- 收到 SIGTERM 后停止接受新房间。
- 通知客户端「服务器维护」。
- 等待进行中对局结束或超时。
- 保存必要状态（如启用 Redis）。
- 再退出进程。

## 11. 安全

### 11.1 基础

- SSH 密钥登录，禁用 root 密码登录。
- 防火墙只开 22/80/443。
- 定期更新系统。
- Docker 容器使用非 root 用户。
- 不在镜像/代码仓库中存密钥。
- 数据库/Redis 不暴露公网。

### 11.2 应用

- JWT 校验。
- 消息大小/频率限制。
- 房间号加入限流。
- 输入合法性校验。
- 错误信息不泄露堆栈/内部路径。
- 反作弊规则见 TDD。

### 11.3 网络

- 全站 HTTPS/WSS。
- 可选 WAF/DDoS 基础防护。
- 限制单 IP 连接数。
- 监控异常流量。

### 11.4 密钥

- AppSecret 泄露立即在微信后台重置。
- JWT_SECRET 轮换会导致旧 token 失效，需评估。
- 使用密码管理器保存密钥。
- 不在聊天/文档中明文传播。

## 14. 常见故障处理

| 现象 | 排查 | 处理 |
|---|---|---|
| 真机连不上服务器 | 域名/证书/合法域名/端口 | 用 `curl`/`openssl` 检查；重新配置微信后台 |
| WebSocket 频繁断开 | 心跳/代理超时/Caddy 配置 | 调大超时；检查 Upgrade 头 |
| 房间创建失败 | 内存/房间号冲突/限流 | 看日志；扩容；清理僵尸房间 |
| 延迟高 | 服务器地域/带宽/tick 堆积 | 换地域；优化 tick；限流 |
| 内存持续上涨 | 房间/定时器/对象未释放 | 做 heap snapshot；修复泄漏；重启临时缓解 |
| 证书过期 | Caddy 自动续期失败 | 手动续期；检查 80 端口 |
| 被刷房间 | 无限流 | 加 IP/openid 限流；WAF；临时封禁 |
| 版本发布后崩溃 | 兼容性/资源缺失 | 回滚版本；检查 CDN 资源 |
