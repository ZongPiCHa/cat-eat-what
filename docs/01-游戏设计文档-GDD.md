# 01 · 游戏设计文档（GDD）

> 版本：v0.1（设计评审稿）  
> 平台：微信小游戏  
> 人数：2-4 人实时联机  
> 单局时长：约 3-5 分钟（含大厅）

---

## 1. 游戏概述

### 1.1 一句话介绍

四只小猫各自选一道想吃的菜，穿过食材跑酷、再端着美食打一场料理大乱斗，最后谁的猫分最高，今晚就吃谁选的菜。

### 1.2 产品定位

- **类型**：2D 休闲、实时多人、轻竞技、社交决策工具。
- **场景**：朋友/同事/情侣在微信群里为「今天吃什么」纠结时，发一局游戏，3-5 分钟出结果。
- **情绪**：温馨、明亮、可爱、轻微的互相打闹，不血腥、不挫败。
- **平台特性**：微信内分享卡片拉人、点开即玩、无需注册账号、无需下载。

### 1.3 设计支柱

1. **可爱优先**：猫、食物、动作都要软萌；失败也有可爱反馈。
2. **3 分钟出结果**：大厅 + 两关控制在一局 3-5 分钟。
3. **低门槛**：只有跳/蹲、摇杆/攻击/闪避，第一次玩也能懂。
4. **轻社交**：公开选餐、实时分数、结算分享；不做自由聊天。
5. **可被审核**：无血腥、无赌博、无诱导分享、无自由 UGC。

### 1.4 目标用户

- 2-4 人小团体，朋友、同事、情侣、室友。
- 微信群里经常为吃什么纠结的人。
- 喜欢猫、喜欢轻量小游戏、愿意分享的人。

### 1.5 单局流程总览

```
首页
  → 创建房间 / 输入房间号加入 / 单人练习
  → 大厅：2-4 个猫座位，公开选餐，房主开始
  → 第一关：食材跑酷（60 秒）
  → 揭晓：每只猫的目标美食
  → 第二关：料理大乱斗（75 秒）
  → 结算：总分最高者获胜，赢家美食 = 今晚答案
  → 再来一局 / 分享结果 / 回首页
```

## 2. 房间与社交流程

### 2.1 创建房间

- 玩家在首页点击「创建房间」。
- 服务端创建 6 位房间号（大写字母 + 数字，排除 `O/0/I/1` 等易混字符）。
- 创建者成为房主，默认坐在 1 号位。
- 房间初始状态：`WAITING`。
- 房间默认最多 4 人，最少 2 人开始。
- 房间空闲 30 分钟自动销毁；游戏结束后 10 分钟无操作销毁。

### 2.2 邀请好友

微信小游戏通过分享卡片邀请，不是普通网页链接。

- 大厅点击「邀请好友」→ 调起微信分享。
- 分享卡片标题示例：`猫猫喊你来决定今晚吃什么！`
- 分享路径携带 `roomId`，例如 `?roomId=7K3M9Q`。
- 好友点击卡片：
  - 冷启动：从启动参数读取 `roomId`，自动加入。
  - 热启动：从 `wx.getEnterOptionsSync()` 读取 `roomId`，自动加入。
- 房间已满/已开始：提示「这局已经开吃啦，等下一局」，并提供「创建一个新房间」。
- 同时提供房间号输入入口，作为分享失败时的兜底。

### 2.3 大厅

大厅展示：

- 房间号、复制/分享按钮。
- 4 个座位：猫头像、猫名字、房主标识、当前选择的美食。
- 6 道美食的选择网格。
- 房主的「开始游戏」按钮。
- 非房主看到「等待房主开始」。
- 离开房间按钮。

规则：

- 玩家可以反复更换美食，直到游戏开始。
- **选餐公开**：所有玩家实时看到每个人选了什么。
- 允许重复选择同一道菜。
- 房主随时可以开始，不要求所有人准备。
- 若有玩家未选餐，开始后自动随机分配，并在倒计时提示「XX 还没选，已帮 TA 随机」。
- 少于 2 人时，开始按钮禁用，提示「再叫一只猫来」。
- 开始后房间锁定，后来者不能进入本局。

### 2.4 房主与离开

- 游戏开始前房主离开：房主自动转移给最早加入的玩家。
- 游戏开始后房主离开：本局继续；结算页的「再来一局」由仍在线的最早加入者发起。
- 玩家主动离开：
  - 大厅阶段：座位释放。
  - 游戏阶段：视为断线，第二关由 AI 接管，座位保留 30 秒。
- 所有玩家离开：房间立即销毁。

### 2.5 断线与重连

- 客户端每 15 秒心跳；30 秒无响应判定断线。
- 重连令牌保存在本地，重新打开小程序自动尝试回到原房间。
- 第一关断线：分数冻结，顶部显示「重连中」；重连后从当前时间点继续，已错过的食材记为未命中。
- 第二关断线：3 秒后 AI 接管，30 秒内重连恢复控制；超过 30 秒座位释放，AI 继续打到本局结束。
- 房主断线：不暂停游戏；房主身份在结算后转移。

### 2.6 再来一局

- 结算页显示「再来一局」（房主/临时房主）。
- 点击后回到大厅，保留当前玩家和美食选择，分数清零。
- 玩家可以重新选餐；房主再次开始。
- 非房主点击「再来一局」时，发送「想再来一局」的提示给房主，不强制开始。

## 3. 美食与食材系统

### 3.1 目标美食

首版固定 6 道菜：

| ID | 美食 | 图标 | 武器外观 | 核心食材（示例） |
|---|---|---|---|---|
| `hotpot` | 火锅 | 🍲 | 大汤勺/小锅 | 辣椒、花椒、牛油、肥牛片、毛肚、土豆片、藕片、豆腐 |
| `malatang` | 麻辣烫 | 🍢 | 漏勺 | 辣椒、花椒、方便面、鱼丸、生菜、豆皮、海带、鹌鹑蛋 |
| `ricebowl` | 盖饭 | 🍚 | 饭勺 | 米饭、鸡蛋、番茄、牛肉、青椒、洋葱、酱油、葱花 |
| `friedchicken` | 炸鸡 | 🍗 | 鸡腿锤 | 鸡肉、面粉、鸡蛋、面包糠、食用油、盐、黑胡椒、生菜 |
| `burger` | 汉堡 | 🍔 | 汉堡盾/汉堡砸 | 面包、牛肉饼、生菜、番茄、芝士、洋葱、酸黄瓜、番茄酱 |
| `pizza` | 披萨 | 🍕 | 披萨回旋 | 面饼、芝士、番茄酱、香肠、蘑菇、青椒、洋葱、橄榄 |

完整食材表与 ID 见 [08-配置数据表.md](./08-配置数据表.md)。

### 3.2 食材判定

- 每道菜有一个「食材集合」。
- 玩家的目标美食决定 TA 的绿色食材集合。
- 食材属于玩家自己的集合 → 绿色，正确。
- 不属于 → 红色，错误。
- 共享食材（辣椒、鸡蛋、番茄、洋葱、青椒、芝士等）对多个人都算正确。
- 如果房间内有人选了盖饭，米饭就会进入本局食材池；对火锅玩家来说，米饭是红色。

### 3.3 干扰食材

如果所有人选了同一道菜，食材池会全是绿色，第一关失去难度。因此需要固定干扰池：

- 米饭、面条、饺子、寿司、蛋糕、西兰花、草莓、牛奶、玉米、包子、沙拉、冰淇淋。
- 生成序列时，过滤掉已经属于本局食材池的干扰项。
- 干扰项占序列的 20%-30%。
- 干扰项对所有玩家都是红色。

### 3.4 食材序列公平性

所有玩家看到**同一条食材序列**，但每个人看到的红绿不同。生成时必须保证：

- 每位玩家的绿色食材数量接近（差值不超过 1-2 个）。
- 食材序列长度固定 24 个。
- 前 3 个食材作为教学，速度放慢；不强制所有玩家都是「绿、红、绿」，但保证每位玩家在前 6 个食材中至少遇到 1 个绿色和 1 个红色。
- 同一个食材不连续出现超过 2 次。
- 干扰项不集中在最后。

具体生成算法见 [02-技术设计文档-TDD.md](./02-技术设计文档-TDD.md) 第 7 节。

### 3.5 选餐公开的影响

选餐公开后：

- 大厅里所有人都能看到彼此的选择，方便社交讨论。
- 玩家可以预判第一关会有哪些「别人的食材」变成红色。
- 第二关开始前会再次高亮展示每只猫的美食与武器。
- 如果两只猫选了同一道菜，它们的绿色食材完全一致，第二关武器也相同。
- 全员选择相同：直接进入结算，展示「全票通过，今晚吃 X」，并提供「友谊赛」按钮。

## 4. 第一关：食材跑酷

### 4.1 体验目标

一只小猫在明亮的美食街上奔跑，食材从右侧飞向猫脸。绿色食材要跳起来吃掉，红色食材要蹲下躲开。操作简单，节奏轻快，60 秒内尽可能多得分。

### 4.2 视角与画面

- 2D 横版侧视。
- 设计分辨率 750 × 1334（竖屏），适配安全区。
- 小猫位于画面左侧约 28% 位置，脚踩地面。
- 食材从右侧飞入，沿水平方向接近猫脸高度。
- 背景三层视差：远景美食街、中景摊位、近景地面/桌布。
- 顶部：分数、其他玩家进度条、倒计时。
- 底部：左右两个大按钮「蹲」「跳」。

### 4.3 操作

| 操作 | 按钮 | 键盘（开发调试） | 动作 |
|---|---|---|---|
| 跳 | 右下大按钮 | `K` / `↑` | 小猫跳起，吃掉嘴部高度的食材 |
| 蹲 | 左下大按钮 | `J` / `↓` | 小猫蹲下，躲开食材 |

- 按钮直径不小于 120px（设计分辨率），触控热区更大。
- 支持 0.15 秒输入缓冲，避免按早了没反应。
- 动作期间不能再次触发，直到动作结束。
- 眩晕期间输入无效。

### 4.4 食材颜色与提示

| 颜色 | 图标 | 含义 | 正确操作 |
|---|---|---|---|
| 绿色光晕 | ✓ | 自己目标美食的食材 | 跳起来吃掉 |
| 红色光晕 | ✗ | 别人的食材或干扰项 | 蹲下躲开 |

- 不能只靠颜色区分：绿光配 ✓，红光配 ✗，并配合不同音效。
- 食材卡片上显示图标 + 名称（如 🌶️ 辣椒）。
- 绿色食材出现时音效轻快；红色食材出现时音效低沉。

### 4.5 判定规则

食材到达猫脸位置的瞬间，根据小猫当前动作判定：

| 食材 | 跳 | 蹲 | 不操作 |
|---|---|---|---|
| 绿色 | **+1 分**，吃掉动画 | 未命中，0 分 | 未命中，0 分 |
| 红色 | **吃到错误食材**：眩晕 1.2 秒 + 跳过下一个食材 | 安全躲开 | **被砸到**：眩晕 1.2 秒 + 跳过下一个食材 |

补充规则：

- 眩晕期间小猫头顶转圈、眼睛变成蚊香眼。
- 眩晕 1.2 秒，刚好覆盖下一个食材到达的时间；下一个食材直接标记为「跳过」，不参与判定。
- 如果眩晕发生在最后 1-2 个食材，剩余食材全部跳过。
- 绿色食材被跳过不影响分数，也没有额外惩罚。
- 第一关不扣分。
- 连击只做视觉提示，不加分（首版不做连击倍率）。

### 4.6 节奏与难度

| 参数 | 数值 |
|---|---|
| 食材总数 | 24 |
| 关卡时长 | 60 秒 |
| 开始倒计时 | 3 秒 |
| 前 3 个食材间隔 | 3.0 秒（教学） |
| 常规食材间隔 | 2.2 秒 |
| 食材飞行时间 | 2.0 秒（教学）→ 1.4 秒（逐渐加快） |
| 跳跃动作时长 | 0.55 秒 |
| 蹲下动作时长 | 0.60 秒 |
| 眩晕时长 | 1.2 秒 |
| 输入缓冲 | 0.15 秒 |

难度曲线：

- 第 1-3 个：教学，慢速。
- 第 4-12 个：常规速度。
- 第 13-20 个：飞行时间缩短到 1.6 秒。
- 第 21-24 个：飞行时间缩短到 1.4 秒，出现连续红绿交替。
- 不增加食材数量，避免单局过长。

### 4.7 HUD

- 左上角：自己的分数。
- 顶部中间：倒计时。
- 顶部右侧/下方：其他玩家的猫头像 + 分数 + 进度条。
- 进度条表示对方已经处理到第几个食材，不显示红绿。
- 自己的分数变化时播放数字跳动。
- 眩晕时屏幕轻微摇晃，不遮挡视线。

### 4.8 教学

第一次进入第一关时显示 3 秒提示：

```
绿色 ✓ 跳起来吃掉
红色 ✗ 蹲下躲开
```

- 教学期间速度放慢。
- 生成算法保证每位玩家在前 6 个食材中至少遇到 1 个绿色和 1 个红色，避免一上来全是同色。
- 教学只出现一次，可在设置中重看。

### 4.9 第一关结算

- 24 个食材处理完或 60 秒倒计时结束。
- 显示「第一关完成」+ 当前分数 + 排名。
- 停留 3 秒，展示每只猫的目标美食。
- 自动进入第二关倒计时。

### 4.10 异常处理

| 情况 | 处理 |
|---|---|
| 切后台 | 本地模拟暂停；回到前台后按服务器时间继续，错过的食材记为未命中 |
| 断线 | 分数冻结，顶部显示「重连中」；重连后继续 |
| 低帧率 | 逻辑按固定时间步推进，渲染掉帧不影响判定 |
| 延迟高 | 第一关本地模拟，不受网络延迟影响；只影响进度上报 |
| 玩家昵称/头像 | 首版不做自定义，使用系统分配的猫名和猫色 |

## 5. 第二关：料理大乱斗

### 5.1 体验目标

四只猫在餐桌上打闹，每人拿着自己选的美食当武器。左侧摇杆移动，右侧攻击和闪避。被击中 -1 分，分数最低 0 分。75 秒后总分最高者获胜。

### 5.2 视角与画面

- 2D 俯视角。
- 固定擂台，不滚动镜头；所有玩家始终可见。
- 设计分辨率 750 × 1334。
- 擂台为圆角矩形/野餐垫，周围是餐具、桌布、食物装饰。
- 每只猫头顶显示猫名、分数、目标美食图标。
- 被击中时不流血：星星、酱汁、晕眩、猫毛炸开。
- 擂台内可加入 1-2 个软障碍（小凳子/果盘），首版建议不加，保证移动顺畅。

### 5.3 操作

| 操作 | 位置 | 说明 |
|---|---|---|
| 移动 | 左下虚拟摇杆 | 8 方向，力度决定速度 |
| 攻击 | 右下按钮 A | 近战挥击，短前摇 |
| 闪避 | 右下按钮 B | 向移动方向短冲刺，有无敌帧 |

- 摇杆半径 100px，按钮直径 110px。
- 支持多点触控：左手摇杆 + 右手按钮同时操作。
- 攻击/闪避有冷却环和置灰反馈。
- 网络延迟高时，按钮按下立即播放动作，命中以服务器为准。

### 5.4 战斗规则

| 规则 | 数值 |
|---|---|
| 移动速度 | 260 单位/秒（世界坐标 1000×1000） |
| 攻击前摇 | 0.18 秒 |
| 攻击判定 | 0.12 秒 |
| 攻击后摇 | 0.50 秒 |
| 攻击冷却 | 0.80 秒（从攻击结束开始） |
| 攻击范围 | 90 单位 |
| 攻击角度 | 100° 扇形 |
| 单次挥击命中同一目标 | 1 次 |
| 命中伤害 | 对方 -1 分 |
| 击退 | 220 单位/秒冲量，快速衰减 |
| 受击无敌 | 0.6 秒 |
| 闪避时长 | 0.22 秒 |
| 闪避速度 | 600 单位/秒 |
| 闪避无敌 | 0.3 秒 |
| 闪避冷却 | 1.8 秒 |
| 0 分保护 | 仍被击退/眩晕，但分数不再下降 |

补充规则：

- 攻击者不加分（原始设计）。如果实测节奏太保守，可在配置中开启 `attackerScore: 1`。
- 同一次攻击不会重复命中同一目标。
- 攻击方向由当前朝向决定；移动方向自动更新朝向。
- 闪避方向优先取摇杆方向；没有输入时向当前朝向闪避。
- 被击中后短暂硬直 0.15 秒，不打断受击无敌。
- 0 分玩家被击中时显示「0 分保护」小盾牌，不扣分。
- 不使用血量、不死亡、不复活，保证 75 秒内所有人持续参与。

### 5.5 分数与排名

- 第二关开始时，总分 = 第一关分数。
- 第二关每次被击中 -1，最低 0 分。
- 顶部实时显示四只猫的总分和排名。
- 第二关没有额外加分项，避免滚雪球。
- 最终总分最高者获胜。

### 5.6 时长与节奏

- 总时长 75 秒。
- 60 秒时提示「最后 15 秒」。
- 70 秒时屏幕边缘轻微脉冲，音乐加快。
- 75 秒结束，进入结算。
- 如果平局：15 秒加时，先命中者获胜；仍无命中则「双拼」。
- 加时期间分数不再变化，只判定第一次有效命中。

### 5.7 武器外观

武器不改变数值，只改变外观和命中特效，保证公平。

| 美食 | 武器 | 攻击特效 |
|---|---|---|
| 火锅 | 大汤勺/小锅 | 红油飞溅、辣椒星 |
| 麻辣烫 | 漏勺 | 汤汁水滴、丸子弹跳 |
| 盖饭 | 饭勺 | 米粒飞散 |
| 炸鸡 | 鸡腿锤 | 脆皮碎屑、油星 |
| 汉堡 | 汉堡盾/汉堡砸 | 生菜叶、芝麻 |
| 披萨 | 披萨回旋 | 芝士拉丝、番茄酱点 |

### 5.8 AI 接管

- 玩家断线 3 秒后 AI 接管。
- AI 行为：
  - 寻找最近的玩家。
  - 保持攻击距离，冷却好就攻击。
  - 被攻击时有 30% 概率闪避。
  - 不主动送分，但也不会过于无敌。
- AI 难度可配置；审核模式和单人练习使用中等 AI。
- 玩家重连后立即交还控制权。

### 5.9 HUD

- 顶部：四只猫的头像、猫名、美食图标、分数、排名。
- 自己高亮显示。
- 自己的分数旁边显示「0 分保护」状态。
- 左下摇杆，右下攻击/闪避按钮及冷却环。
- 中间偏上显示倒计时。
- 命中时飘字 `-1`，受击者屏幕边缘闪一下暖色，不刺眼。

### 5.10 结算

- 显示获胜猫的大头贴、名字、目标美食。
- 大字：`今晚吃火锅！`
- 下方四行总分排名。
- 如果平局且双拼：显示两道菜 `今晚吃火锅 + 披萨！`
- 按钮：
  - `就吃这个`（分享结果卡片）
  - `再来一局`（房主）
  - `回大厅`
- 分享文案示例：`猫猫们打完了，今晚吃火锅！`
- 不出现「愿赌服输」等带赌博意味的文案。

## 6. 计分与胜负

### 6.1 总分公式

```
最终总分 = 第一关正确食材数 + 第二关得分变化
第二关最低 0 分
```

### 6.2 排名

- 按最终总分从高到低。
- 同分：
  1. 15 秒加时，分数锁定，先命中者胜。
  2. 加时仍无命中 → 双拼，两样都吃。
- 首版如果不想做加时，可以直接双拼；规则在配置中开关。

### 6.3 全员同菜

- 大厅检测到所有玩家选择相同美食。
- 开始后直接进入结算：
  - 展示 `全票通过！今晚吃火锅`
  - 放庆祝动画
  - 提供 `友谊赛`（进入两关）和 `再来一局`（重新选餐）
- 这样既尊重「决定吃什么」的目标，也不会浪费大家时间。

### 6.4 单人练习

- 首页提供「单人练习」。
- 玩家 + 3 个 AI 猫，完整走两关。
- 用于：
  - 新手熟悉操作。
  - 审核员体验完整流程。
  - 服务器无人时也能玩。
- 练习模式不计入排行榜，不产生房间。

## 9. MVP 范围

### 9.1 首版必须做

- 创建/加入房间、分享邀请、2-4 人。
- 公开选餐、房主开始、未选随机。
- 第一关完整规则、教学、计分。
- 第二关完整规则、摇杆/攻击/闪避、计分。
- 结算、再来一局、分享结果。
- 断线重连、AI 接管、房主迁移。
- 单人练习 + 3 AI。
- 音效、BGM、静音开关。
- 隐私政策、用户协议、版本号。
- 基础埋点与错误上报。

### 9.2 首版不做

- 自由聊天、语音。
- 好友排行榜、赛季、段位。
- 内购、广告、虚拟货币。
- 自定义昵称/头像/猫皮肤。
- 观战、中途加入。
- 更多美食、更多关卡、道具。
- 跨平台（仅微信小游戏）。
- 海外版。

### 9.3 后续可扩展

- 快速表情/预设短语（需审核）。
- 2v2 组队。
- 美食图鉴、成就。
- 每日挑战、周榜。
- 自定义房间规则（时长、食材数量）。
- 更多猫皮肤（不影响数值）。
- 结果页分享战绩长图。

## 10. 验收标准

### 10.1 功能验收

- 2-4 人可以从分享卡片进入同一房间。
- 所有人能看到彼此选餐，换餐实时同步。
- 房主随时开始；未选餐自动随机。
- 第一关 24 个食材，绿/红判定和眩晕跳过规则正确。
- 第二关移动、攻击、闪避、命中、0 分保护正确。
- 总分排名正确，平局按配置处理。
- 断线重连、AI 接管、房主迁移可用。
- 4 台真机、弱网、切后台测试通过。
- 审核员可通过单人练习体验完整流程。

### 10.2 体验验收

- 新玩家不看说明也能在 10 秒内理解跳/蹲。
- 单局 3-5 分钟内结束。
- 第一关有紧张感但不挫败。
- 第二关有互动和笑声，不是各玩各的。
- 输家也愿意再来一局。
- 结算页一眼看懂「今晚吃什么」。

### 10.3 技术验收

- 第二关 20Hz 快照，端到端延迟目标 < 150ms（同省 4G/5G）。
- 连续 30 分钟无内存泄漏、无房间卡死。
- 单实例支持 50 个活跃房间（200 CCU）压测通过。
- 崩溃率、卡顿率、断线率有监控。
- 服务端重启不影响已结束对局的数据记录（首版可不落库）。

## 11. 设计风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 两个游戏 = 两倍工作量 | 跑酷和大乱斗的操作、美术、网络都不同 | 先做第一关，第二关用最小可行版本；共用猫和 UI |
| 公开选餐导致策略透明 | 大家知道彼此的菜，第一关红色食材可预判 | 这是社交乐趣；用干扰项保证难度 |
| 全员同菜 | 决策提前完成，第一关全绿 | 直接结算 + 友谊赛 |
| 第二关被集火 | 落后玩家被围攻，体验差 | 0 分保护、受击无敌、击退；实测后调数值 |
| 攻击者不加分 | 大家可能不爱打架 | 配置开关，可改为击中 +1 |
| 第一关公平性 | 食材序列对不同玩家难度不同 | 均衡生成算法 + 每局校验绿食材数量 |
| 审核门槛 | 版号周期长 | 提前启动；先体验版内测 |
| 多人审核难 | 审核员凑不齐 2 人 | 单人练习 + AI，完整可玩 |
| 自由聊天风险 | UGC 审核成本高 | 首版不做，只做预设表情（后续） |
