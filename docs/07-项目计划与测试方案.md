# 07 · 项目计划与测试方案

> 目标：从设计稿到公开上架，给出可执行的里程碑、分工、风险和测试清单。  
> 说明：周期按小团队/兼职投入估算，实际取决于美术量、版号进度和联网调试。

---

## 1. 项目范围

### 1.1 首版 MVP

- 微信小游戏，2-4 人实时房间。
- 公开选餐，6 道固定美食。
- 第一关食材跑酷（60 秒）。
- 第二关料理大乱斗（75 秒）。
- 总分结算、获胜美食、再来一局、分享结果。
- 断线重连、AI 接管、房主迁移。
- 单人练习 + 3 AI。
- 隐私/防沉迷/审核模式。
- 基础埋点、日志、监控。

### 1.2 首版不做

- 自由聊天/语音。
- 排行榜/赛季/段位。
- 内购/广告。
- 自定义昵称/头像/皮肤。
- 观战/中途加入。
- 更多美食/关卡/道具。
- 海外版/跨平台。

### 1.3 成功标准

- 4 人真机完整对局成功率 > 95%。
- 单局 3-5 分钟，结算后愿意再来一局。
- 第二关同省延迟 < 150ms，弱网可恢复。
- 审核员可通过单人练习完整体验。
- 公开上架资质齐全，审核通过。

## 2. 团队与分工

### 2.1 最小团队

| 角色 | 人数 | 职责 |
|---|---|---|
| 客户端 | 1 | Cocos、UI、动画、联网、微信 API |
| 服务端 | 1 | 房间、同步、登录、部署、监控 |
| 美术 | 1 | 角色、场景、UI、特效、分享图 |
| 项目/QA | 0.5-1 | 排期、资质、测试、审核材料 |

### 2.2 单人 + AI 方案

- 客户端/服务端由一人 + AI 完成。
- 美术先 emoji/占位，后期外包。
- 周期延长到 3-5 个月。
- 瓶颈通常是美术、真机测试、版号，不是写代码。

### 2.3 外部合作

- 版号出版单位/代理。
- 美术外包/音效外包。
- 法务/隐私顾问（按需）。
- 服务器/云厂商。

## 3. 里程碑

### 3.1 总览

| 阶段 | 内容 | 周期 | 出口条件 |
|---|---|---|---|
| M0 | 文档与设计 | 1 周 | 本套文档评审通过 |
| M1 | 资质启动 | 并行 | 主体/认证/软著/版号渠道启动 |
| M2 | 技术验证 | 1 周 | Cocos 导出、WSS、2 客户端互通 |
| M3 | 本地纵切 | 2-3 周 | 第一关 + 第二关 + AI 可玩 |
| M4 | 在线大厅 | 2 周 | 创建/加入/分享/公开选餐/开始 |
| M5 | 第一关联网 | 2 周 | 序列、进度、结算、重连 |
| M6 | 第二关联网 | 2-3 周 | 20Hz 同步、命中、AI、重连 |
| M7 | 美术/音频/UI | 3-4 周 | 可发布品质 |
| M8 | 合规/审核 | 2 周 + 等待 | 隐私/防沉迷/审核材料 |
| M9 | 体验版内测 | 1-2 周 | 4 人真机稳定 |
| M10 | 正式发布 | 版号后 | 审核通过、监控就绪 |

**开发总周期：约 10-14 周（小团队全职）；兼职 3-5 个月。**  
**版号：6-12+ 个月，必须与开发并行。**

### 3.2 详细排期（全职小团队）

#### 第 1 周：M0 + M2

- 文档评审、规则定稿。
- 注册/认证/备案/软著/版号咨询启动。
- Cocos 空工程导出微信小游戏。
- Node 服务 + WSS + 2 个客户端互发消息。
- 确认 Cocos 在微信小游戏里的 WebSocket、分享、音频、隐私 API。

#### 第 2-4 周：M3 本地纵切

- 首页/大厅/关卡/结算场景。
- 第一关完整规则 + 占位美术。
- 第二关摇杆/攻击/闪避 + 3 AI。
- 占位音效、UI。
- 内部试玩，验证手感。

#### 第 5-6 周：M4 在线大厅

- 登录、JWT、WS 鉴权。
- 创建/加入/分享/房间号。
- 公开选餐、房主开始、未选随机。
- 房主迁移、离开、房间超时。
- 2-4 人真机联调。

#### 第 7-8 周：M5 第一关联网

- 序列生成 + 公平性校验。
- 客户端本地模拟 + 进度上报。
- 服务端校验/汇总/排名。
- 断线冻结/重连恢复。
- 第一关完整 4 人测试。

#### 第 9-11 周：M6 第二关联网

- 服务端权威模拟、tick、快照。
- 客户端输入、插值、HUD。
- 命中/击退/无敌/0 分保护。
- 断线 AI、重连、加时/双拼。
- 弱网测试、延迟调优。

#### 第 12-15 周：M7 美术/音频/UI

- 4 只猫动画、6 道美食、食材图标。
- 场景、UI、特效、分享图。
- BGM/SFX。
- 性能优化、低端机适配。
- 隐私政策/用户协议页面。

#### 第 16-17 周：M8 合规/审核

- 实名/防沉迷接入。
- 单人练习/审核模式。
- 审核材料、截图、说明。
- 隐私/内容自查。
- 提交审核。

#### 第 18 周+：M9/M10

- 体验版 4 人内测。
- 修 bug、调数值。
- 版号获批后正式发布。
- 监控、客服、迭代。

> 排期是理想情况；版号、美术返工、联网 bug 都可能拉长。建议按 1.5 倍缓冲做预算。

## 4. 依赖关系

```
文档定稿
  ├─ 资质启动（版号最长，最先做）
  ├─ 技术验证
  │    └─ 本地纵切
  │         ├─ 在线大厅
  │         │    ├─ 第一关联网
  │         │    └─ 第二关联网
  │         └─ 美术/音频
  └─ 合规/审核材料
```

关键依赖：

- 版号 → 正式发布。
- 备案/域名 → 真机联网。
- 美术 → 审核截图/商店素材。
- 单人练习 → 审核通过。
- 服务端稳定 → 审核体验。

## 7. 弱网与异常测试

### 7.1 网络模拟

- 工具：微信开发者工具网络模拟、手机弱网工具、路由器限速。
- 场景：
  - 延迟 100/200/400ms。
  - 丢包 1%/5%/10%。
  - 带宽 200kbps/1Mbps。
  - 断网 3/10/30 秒。
- 观察：
  - 是否崩溃。
  - 是否自动重连。
  - 分数/位置是否一致。
  - 是否出现幽灵玩家/重复扣分。

### 7.2 生命周期

- 切后台 5 秒/1 分钟/10 分钟。
- 锁屏/解锁。
- 来电/视频通话。
- Wi-Fi/4G 切换。
- 低电量模式。
- 系统语言/字体大小变化。

### 7.3 服务器异常

- 重启进程。
- Redis 断开（如启用）。
- 磁盘满。
- 证书过期。
- 带宽打满。
- 大量空房间。

## 8. Playtest 计划

### 8.1 对象

- 5-10 组，每组 2-4 人。
- 朋友、同事、情侣、室友。
- 至少 2 组非游戏行业用户。

### 8.2 流程

1. 不发说明，让用户自己从分享卡片进入。
2. 观察是否知道创建/加入。
3. 观察第一关是否理解跳/蹲。
4. 观察第二关是否理解摇杆/攻击/闪避。
5. 结算后询问是否愿意再来一局。
6. 记录问题，不打断。

### 8.3 问题

- 哪一步卡住了？
- 第一关红绿是否一眼分清？
- 第二关是否知道自己在打谁？
- 75 秒是否太长/太短？
- 输赢是否服气？
- 是否愿意分享给另一个群？
- 最想增加什么？

### 8.4 指标

- 创建房间 → 开始游戏转化率。
- 完整对局完成率。
- 再来一局率。
- 分享率。
- 平均单局时长。
- 崩溃/断线率。
- 主观评分（1-5）：可爱、易懂、好玩、想再来。

## 9. 数据分析

### 9.1 核心漏斗

```
启动
  → 登录成功
  → 创建/加入房间
  → 2 人以上
  → 开始游戏
  → 第一关完成
  → 第二关完成
  → 结算
  → 再来一局 / 分享
```

### 9.3 指标目标

| 指标 | 目标 |
|---|---|

| 完整对局率 | > 85% |

## 10. 上线计划

### 10.1 体验版

- 4 人内测。
- 收集崩溃/延迟/玩法反馈。
- 调第一关/第二关数值。
- 修房间/重连问题。

### 10.2 审核版

- 完成隐私/防沉迷/单人练习。
- 准备审核材料。
- 服务器稳定运行。
- 提交审核。

### 10.3 正式发布

- 小范围发布，观察 24 小时。
- 监控崩溃、延迟、房间创建。
- 准备回滚版本。
- 收集反馈，按周迭代。

### 10.4 发布后

- 每周看漏斗/留存/分享。
- 修复高优 bug。
- 评估是否加新美食/新关卡。
- 不急于加广告/内购。
