# 03 · 网络协议与数据模型

> 版本：v1  
> 传输：HTTPS + WSS  
> 编码：UTF-8 JSON  
> 单条消息上限：4KB  
> 协议版本：`v: 1`

---

## 1. 通用约定

### 1.1 消息信封

所有 WebSocket 消息使用统一信封：

```json
{
  "v": 1,
  "type": "message_type",
  "seq": 12,
  "ts": 1760000000000,
  "payload": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `v` | number | 是 | 协议版本，首版固定 1 |
| `type` | string | 是 | 消息类型 |
| `seq` | number | 客户端消息必填 | 客户端自增序号，服务端用于去重/排序 |
| `ts` | number | 是 | 客户端/服务端发送时间，毫秒 |
| `payload` | object | 是 | 消息体，无内容时传 `{}` |

### 1.2 命名

- 消息类型：小写下划线，如 `create_room`、`level1_start`。
- 字段：小驼峰，如 `roomId`、`playerId`、`serverTime`。
- 枚举：大写下划线，如 `WAITING`、`LEVEL1`。

### 1.3 时间

- 所有时间使用毫秒时间戳。
- 客户端不能信任本地时间做对局同步，以服务器时间为准。
- 服务端使用单调时钟计算对局时长。

### 1.4 错误处理

错误消息：

```json
{
  "v": 1,
  "type": "error",
  "ts": 1760000000000,
  "payload": {
    "code": "ROOM_FULL",
    "message": "房间满啦",
    "requestType": "join_room",
    "requestId": "req_123"
  }
}
```

### 1.5 幂等

- 房间操作带 `requestId`。
- 服务端缓存最近 5 分钟的 `requestId` 结果。
- 重复请求返回同一结果，避免弱网重发导致重复加入/重复开始。

## 2. HTTP 接口

### 2.1 登录

`POST /api/login`

请求：

```json
{
  "code": "wx.login 返回的 code",
  "clientVersion": "1.0.0",
  "platform": "ios"
}
```

响应：

```json
{
  "token": "jwt...",
  "expiresIn": 7200,
  "playerId": "p_abc123",
  "openIdHash": "sha256...",
  "serverTime": 1760000000000
}
```

说明：

- 服务端调用微信 `code2Session`，使用 AppID + AppSecret。
- AppSecret 只在服务端环境变量。
- `openIdHash` 仅用于客户端展示/排查，不返回原始 openid。
- token 有效期 2 小时。

### 2.2 配置

`GET /api/config?version=1`

响应：

```json
{
  "version": 1,
  "foods": [],
  "ingredients": [],
  "constants": {},
  "minClientVersion": "1.0.0",
  "serverTime": 1760000000000
}
```

说明：

- 客户端启动时拉取，失败可用内置兜底配置。
- 配置带版本号，服务端可强制更新。
- 食材/数值变更必须两端兼容。

### 2.3 健康检查

`GET /healthz`

```json
{
  "ok": true,
  "uptime": 12345,
  "rooms": 12,
  "players": 38,
  "version": "1.0.0"
}
```

### 2.4 指标

`GET /metrics`（仅内网/鉴权）

- Prometheus 文本格式，后续接入。
- 首版可只输出 JSON 摘要。

### 2.5 客户端错误上报

`POST /api/log`

```json
{
  "level": "error",
  "message": "TypeError...",
  "stack": "...",
  "clientVersion": "1.0.0",
  "playerId": "p_abc123",
  "roomId": "7K3M9Q",
  "ts": 1760000000000
}
```

- 频率限制：每客户端每分钟 20 条。
- 不包含 token、openid、用户输入内容。
- 首版也可接入微信小游戏自带错误上报。

## 3. WebSocket 生命周期

### 3.1 建立连接

```
客户端 → wss://ws.example.com/ws
客户端 → auth
服务端 → auth_ok
```

- 连接后 5 秒内未 `auth`，服务端断开。
- `auth` 失败返回 `error` 并断开。
- 同一 openid 允许一个活跃连接；新连接踢掉旧连接。

### 3.2 心跳

客户端每 15 秒：

```json
{
  "v": 1,
  "type": "ping",
  "seq": 100,
  "ts": 1760000000000,
  "payload": { "clientTime": 1760000000000 }
}
```

服务端：

```json
{
  "v": 1,
  "type": "pong",
  "ts": 1760000000000,
  "payload": {
    "clientTime": 1760000000000,
    "serverTime": 1760000000000
  }
}
```

- 服务端 30 秒无消息断开。
- 客户端 30 秒无 `pong` 判定断线。

### 3.3 重连

客户端重连后发送：

```json
{
  "v": 1,
  "type": "auth",
  "seq": 1,
  "ts": 1760000000000,
  "payload": {
    "token": "jwt...",
    "roomId": "7K3M9Q",
    "reconnectToken": "rt_abc..."
  }
}
```

服务端根据状态返回：

- `auth_ok` + `room_state` + `level1_state` / `level2_state` / `match_result`。
- 或 `error`（房间已销毁、座位已释放）。

## 4. 客户端 → 服务端消息

### 4.1 `auth`

```json
{
  "v": 1,
  "type": "auth",
  "seq": 1,
  "ts": 1760000000000,
  "payload": {
    "token": "jwt...",
    "roomId": "7K3M9Q",
    "reconnectToken": "rt_abc..."
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `token` | 是 | 登录 token |
| `roomId` | 否 | 重连/直接进房时携带 |
| `reconnectToken` | 否 | 重连令牌 |

### 4.2 `create_room`

```json
{
  "v": 1,
  "type": "create_room",
  "seq": 2,
  "ts": 1760000000000,
  "payload": {
    "requestId": "req_001",
    "catSkin": "orange"
  }
}
```

响应：`room_state`。

### 4.3 `join_room`

```json
{
  "v": 1,
  "type": "join_room",
  "seq": 3,
  "ts": 1760000000000,
  "payload": {
    "requestId": "req_002",
    "roomId": "7K3M9Q",
    "catSkin": "cow"
  }
}
```

响应：`room_state`。

### 4.4 `leave_room`

```json
{
  "v": 1,
  "type": "leave_room",
  "seq": 4,
  "ts": 1760000000000,
  "payload": {
    "roomId": "7K3M9Q"
  }
}
```

响应：`left_room`。

### 4.5 `select_food`

公开选餐，服务端广播给房间所有人。

```json
{
  "v": 1,
  "type": "select_food",
  "seq": 5,
  "ts": 1760000000000,
  "payload": {
    "foodId": "hotpot"
  }
}
```

响应：`room_state`（广播）。

### 4.6 `start_game`

仅房主可发。

```json
{
  "v": 1,
  "type": "start_game",
  "seq": 6,
  "ts": 1760000000000,
  "payload": {
    "requestId": "req_003"
  }
}
```

说明：

- 少于 2 人返回 `NOT_ENOUGH_PLAYERS`。
- 未选餐玩家由服务端随机分配，并在 `level1_start` 前广播。
- 房间锁定，拒绝新玩家。

响应：`game_start` + `level1_start`。

### 4.7 `level1_progress`

```json
{
  "v": 1,
  "type": "level1_progress",
  "seq": 7,
  "ts": 1760000000000,
  "payload": {
    "index": 8,
    "score": 5
  }
}
```

- 每处理一个食材上报一次，或每 0.5 秒一次。
- 服务端用于进度条、断线恢复、校验。
- 频率限制：每 200ms 最多 1 次。

### 4.8 `level1_result`

```json
{
  "v": 1,
  "type": "level1_result",
  "seq": 8,
  "ts": 1760000000000,
  "payload": {
    "score": 14,
    "processed": 24,
    "greenCount": 16
  }
}
```

- 客户端上报最终分数。
- 服务端校验后汇总。
- 超时未上报使用最后进度。

### 4.9 `input`

第二关输入，30Hz。

```json
{
  "v": 1,
  "type": "input",
  "seq": 9,
  "ts": 1760000000000,
  "payload": {
    "seq": 42,
    "moveX": 0.7,
    "moveY": -0.2,
    "attack": false,
    "dodge": true,
    "clientTime": 1760000000000
  }
}
```

| 字段 | 说明 |
|---|---|
| `seq` | 输入序号，服务端丢弃旧序号 |
| `moveX/moveY` | 归一化输入，长度 <= 1 |
| `attack` | 本帧是否按下攻击 |
| `dodge` | 本帧是否按下闪避 |
| `clientTime` | 客户端时间，用于延迟统计 |

### 4.10 `ping`

见 3.2。

### 4.11 `rematch`

```json
{
  "v": 1,
  "type": "rematch",
  "seq": 10,
  "ts": 1760000000000,
  "payload": {
    "requestId": "req_004"
  }
}
```

- 房主/临时房主发起。
- 回到大厅，保留玩家和美食，分数清零。
- 非房主发送时，服务端广播「XX 想再来一局」。

### 4.12 `emote`（首版不做，预留）

```json
{
  "v": 1,
  "type": "emote",
  "seq": 11,
  "ts": 1760000000000,
  "payload": {
    "emoteId": "cheer"
  }
}
```

- 仅预设表情，不接受自由文本。
- 需要内容审核评估后再开放。

## 6. 数据模型

### 6.1 `Player`

| 字段 | 类型 | 说明 |
|---|---|---|
| `playerId` | string | 服务端内部 ID |
| `openId` | string | 仅服务端保存，不广播 |
| `nickname` | string | 系统生成，如「橘猫」 |
| `catSkin` | enum | `orange`/`cow`/`black`/`calico` |
| `seat` | number | 0-3 |
| `foodId` | string \| null | 目标美食 |
| `score` | number | 总分 |
| `level1Score` | number | 第一关分数 |
| `level2Score` | number | 第二关分数 |
| `connected` | boolean | 是否在线 |
| `isBot` | boolean | 是否 AI |
| `isHost` | boolean | 是否房主 |
| `botLevel` | number | AI 难度 |

### 6.2 `Room`

| 字段 | 类型 | 说明 |
|---|---|---|
| `roomId` | string | 6 位房间号 |
| `hostId` | string | 房主 playerId |
| `status` | enum | `WAITING`/`LEVEL1`/`TRANSITION`/`LEVEL2`/`RESULT` |
| `maxPlayers` | number | 4 |
| `minPlayers` | number | 2 |
| `players` | Player[] | 玩家列表 |
| `createdAt` | number | 创建时间 |
| `updatedAt` | number | 最后活跃时间 |

### 6.3 `Level1State`

| 字段 | 类型 | 说明 |
|---|---|---|
| `sequence` | string[] | 食材 ID 序列 |
| `startAt` | number | 开始时间 |
| `durationMs` | number | 60000 |
| `itemIntervalMs` | number | 2200 |
| `travelTimeMs` | number | 1800 |
| `greenCountByPlayer` | Map | 每位玩家的绿色食材数量 |
| `progress` | Map | 玩家进度/分数 |
| `results` | Map | 最终结果 |
| `suspicious` | Set | 异常玩家 |

### 6.4 `Level2State`

| 字段 | 类型 | 说明 |
|---|---|---|
| `startAt` | number | 开始时间 |
| `durationMs` | number | 75000 |
| `tick` | number | 当前 tick |
| `players` | Map | 位置、分数、状态 |
| `inputs` | Map | 最新输入 |
| `events` | array | 本 tick 事件 |
| `overtime` | boolean | 是否加时 |
| `overtimeWinner` | string \| null | 加时首次命中者 |

### 6.5 `MatchResult`

| 字段 | 类型 | 说明 |
|---|---|---|
| `winnerIds` | string[] | 赢家 |
| `isTie` | boolean | 是否平局 |
| `isDoubleMeal` | boolean | 是否双拼 |
| `foods` | string[] | 获胜美食 |
| `ranking` | array | 排名 |
| `reason` | string | `timeout`/`overtime`/`unanimous` |

## 7. 枚举

### 7.1 `RoomStatus`

| 值 | 说明 |
|---|---|
| `WAITING` | 大厅选餐 |
| `LEVEL1` | 第一关 |
| `TRANSITION` | 关卡过渡 |
| `LEVEL2` | 第二关 |
| `RESULT` | 结算 |

### 7.2 `PlayerState`（第二关）

| 值 | 说明 |
|---|---|
| `idle` | 正常 |
| `windup` | 攻击前摇 |
| `active` | 攻击判定 |
| `recovery` | 攻击后摇 |
| `dodge` | 闪避 |
| `hit` | 受击硬直 |

### 7.3 `FoodId`

`hotpot` / `malatang` / `ricebowl` / `friedchicken` / `burger` / `pizza`

### 7.4 `CatSkin`

`orange` / `cow` / `black` / `calico`

### 7.5 `ErrorCode`

| 错误码 | 说明 |
|---|---|
| `AUTH_FAILED` | 登录失败/token 无效 |
| `AUTH_REQUIRED` | 未认证 |
| `ROOM_NOT_FOUND` | 房间不存在 |
| `ROOM_FULL` | 房间已满 |
| `ROOM_STARTED` | 游戏已开始 |
| `NOT_IN_ROOM` | 不在房间 |
| `NOT_HOST` | 不是房主 |
| `NOT_ENOUGH_PLAYERS` | 人数不足 |
| `INVALID_FOOD` | 美食 ID 无效 |
| `INVALID_MESSAGE` | 消息格式错误 |
| `RATE_LIMITED` | 频率过高 |
| `SERVER_BUSY` | 服务繁忙 |
| `VERSION_MISMATCH` | 客户端版本过低 |
| `RECONNECT_EXPIRED` | 重连窗口已过 |
| `INTERNAL_ERROR` | 服务端内部错误 |

## 8. 校验与限流

### 8.1 消息校验

- 必须有 `v`、`type`、`ts`、`payload`。
- `v` 必须为 1。
- `type` 必须在白名单。
- 消息大小 <= 4KB。
- 字符串长度限制：foodId <= 32，roomId = 6，requestId <= 64。
- 数值必须是有限数，拒绝 NaN/Infinity。

### 8.2 频率限制

| 操作 | 限制 |
|---|---|
| WS 消息 | 60 条/秒/连接 |
| `input` | 40 条/秒 |
| `level1_progress` | 5 条/秒 |
| `join_room` | 10 次/分钟/openid |
| `create_room` | 5 次/分钟/openid |
| `select_food` | 10 次/秒 |
| HTTP `/api/login` | 20 次/分钟/IP |
| HTTP `/api/log` | 20 条/分钟/客户端 |

### 8.3 房间操作幂等

- `create_room`、`join_room`、`start_game`、`rematch` 带 `requestId`。
- 服务端缓存结果 5 分钟。
- 相同 `requestId` 返回缓存响应，不重复执行。

## 9. 完整对局示例

### 9.1 创建房间

```
C → create_room {requestId:"r1", catSkin:"orange"}
S → room_state {roomId:"7K3M9Q", hostId:"p1", players:[...]}
```

### 9.2 好友加入

```
C2 → join_room {requestId:"r2", roomId:"7K3M9Q", catSkin:"cow"}
S → room_state (C2)
S → player_joined (C1)
```

### 9.3 公开选餐

```
C1 → select_food {foodId:"hotpot"}
S → room_state (广播)
C2 → select_food {foodId:"pizza"}
S → room_state (广播)
```

### 9.4 开始

```
C1 → start_game {requestId:"r3"}
S → game_start {startAt, players}
S → level1_start {sequence, startAt, ...}
C1/C2 → level1_progress / level1_result
S → level1_end {ranking, foods}
S → level2_start {players, arena}
C1/C2 → input (30Hz)
S → snapshot (20Hz)
S → game_over {winnerIds, foods, ranking}
```

### 9.5 断线重连

```
C2 断线
S → player_disconnected (C1)
C2 重连 → auth {token, roomId, reconnectToken}
S → auth_ok + room_state + level2_state + snapshot
S → player_reconnected (C1)
```

## 10. 协议演进

- 首版固定 `v:1`。
- 新增字段必须向后兼容，客户端忽略未知字段。
- 删除/修改字段必须升级版本。
- 服务端保留至少 2 个版本的兼容窗口。
- 客户端启动时检查 `minClientVersion`，过低强制更新。
- 协议类型定义放在 `packages/shared/src/protocol.ts`，两端同步。
