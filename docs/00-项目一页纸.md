# 00 · 项目一页纸

> 用于快速了解项目，也方便给合作方、出版单位、美术/外包团队看。

## 项目名称

**猫猫今天吃什么**（暂定，上线前做商标检索）

## 一句话

2-4 只猫各自选一道想吃的菜，通过「食材跑酷」和「料理大乱斗」两关决出胜负，赢家选的美食就是今晚的答案。

## 基本信息

| 项目 | 内容 |
|---|---|
| 类型 | 2D 休闲、实时多人、轻竞技、社交决策 |
| 平台 | 微信小游戏 |
| 人数 | 2-4 人 |
| 单局 | 3-5 分钟 |
| 视角 | 第一关横版侧视；第二关俯视角 |
| 风格 | 温馨、明亮、可爱、贴纸绘本 |
| 目标用户 | 朋友、同事、情侣、室友；为「吃什么」纠结的小团体 |
| 核心场景 | 微信群里发一局，3 分钟出结果 |

## 核心循环

```
创建房间 → 分享到微信群 → 好友点击加入
  → 每人公开选一道菜
  → 第一关：食材跑酷（60 秒）
  → 第二关：料理大乱斗（75 秒）
  → 总分最高者的美食获胜
  → 分享结果 / 再来一局
```

## 两关玩法

### 第一关：食材跑酷

- 每道菜拆成食材：火锅 = 辣椒、花椒、牛油、肥牛片、毛肚、土豆片、藕片、豆腐。
- 食材飞向猫脸，绿色 ✓ 跳起来吃，红色 ✗ 蹲下躲。
- 正确 +1；吃到错误食材眩晕 1.2 秒，并跳过下一个食材。
- 60 秒 / 24 个食材；所有人看到同一条序列，但红绿因各自美食不同。

### 第二关：料理大乱斗

- 俯视角固定擂台，四只猫拿着自己的美食当武器。
- 左侧摇杆移动，右侧攻击/闪避。
- 命中对方 -1 分，最低 0 分；受击有无敌帧，0 分有保护。
- 75 秒结束，总分最高者获胜；平局加时，仍平局则双拼。

## 差异化

- **真的能解决「吃什么」**：不是纯竞技，赢家美食就是今晚答案。
- **选餐公开**：大厅就能看到朋友的选择，天然有话题。
- **两关情绪互补**：第一关个人专注，第二关多人打闹。
- **低门槛**：只有跳/蹲、摇杆/攻击/闪避，点开即玩。
- **可爱但不低幼**：猫 + 食物 + 轻竞技，适合年轻用户。

## 技术方案

| 层 | 方案 |
|---|---|
| 客户端 | Cocos Creator 3.8 LTS + TypeScript |
| 服务端 | Node.js 20 + TypeScript + WebSocket |
| 同步 | 第一关客户端模拟 + 服务端校验；第二关 20Hz 服务器权威 |
| 部署 | 腾讯云轻量 2C4G + Docker + Caddy；单实例起步 |
| 存储 | 首版内存；Redis/PostgreSQL 后续 |
| 资源 | COS/CDN |

## 关键合规

- 公开上架微信小游戏需要**游戏版号**，周期可能 6-12 个月。
- 需要企业主体、微信认证、小程序/小游戏备案、软著、实名/防沉迷、隐私政策。
- 首版无内购、无广告、无自由聊天，降低审核风险。
- 提供「单人练习 + 3 AI」，让审核员无需好友即可体验完整流程。

| 软著 | 0-2000 元 |
| 版号 | 数万元级起，以出版单位报价为准 |
| 美术/音频 | 按外包/全职成本 |

## 主要风险

1. 版号周期长/不批 → 先体验版，尽早找出版单位。
2. 第二关实时同步手感 → 第 1 周技术验证，插值/预测可调。
3. 两个游戏 = 两倍工作量 → 先做第一关，第二关最小可行。
4. 美术量超预期 → emoji/占位先行，核心外包。
5. 审核员无法组队 → 单人练习 + AI + 审核说明。
6. 公开选餐/全员同菜 → 直接结算 + 友谊赛。
